## 逐条复测

### F-01 购物车金额语义

- **复测动作**：加购单价 18 的菜品 → 数量改 2 → 读取 `shoppingCart/list` → 下单。
- **实际结果**：`amount=18`（单价）、`number=2`，前端行小计显示 36.00，合计 36.00；订单 `orderAmount=36`。
- **结论**：前端按 `单价×数量` 展示后与后端记账一致；契约字段名仍建议改为 `unitPrice` 或在描述中注明。
- **证据**：`evidence/api-smoke.json`（购物车组、订单组）。

### F-02 支付幂等

- **复测动作**：同一订单连续调用两次 `PUT /user/order/payment`。
- **实际结果**：两次均 `code=1`，`packageStr` 相同（`SIMULATED:<订单号>`），订单无二次变更。
- **结论**：实现是有意幂等；契约只写了通用 409，建议补一句幂等说明。前端仍保留按钮 loading 防重复点击。
- **证据**：`evidence/api-exceptions.json`（幂等两项）。

### F-03 dish/list 返回类型

- **复测动作**：`GET /user/dish/list` 后检查 `data[0].flavors`。
- **实际结果**：返回数组，元素含 `flavors`（`DishVO` 结构），前端可渲染“辣度：不辣/微辣/中辣”。
- **结论**：页面可用；契约（`Dish`）与实现（`DishVO`）不一致，需组长修订契约或补说明。
- **证据**：`evidence/api-smoke.json`（浏览组 `hasFlavors=true`）。

### F-04 缺菜品详情接口

- **复测动作**：菜品详情页改为 `GET /user/dish/list` 全量后按 id 定位。
- **实际结果**：能展示在售菜品详情与口味；已停售菜品会提示“不存在或已停售”。
- **结论**：功能可用但多一次请求；建议增补 `GET /user/dish/{id}`。

### F-05 口味 JSON 字符串

- **复测动作**：管理端新增/编辑菜品口味（输入“不辣,微辣,中辣”）→ 用户端查看 → 购物车加购。
- **实际结果**：保存为 `["不辣","微辣","中辣"]`，两端解析正常。
- **证据**：`evidence/browser-check.json`（首页渲染口味行）、管理端菜品页截图。

### F-07 `/assets/` 前缀冲突

- **复测动作**：按修正后的规则重新部署 dist（`serve-dist.mjs` 8081/8082）→ 请求入口 JS、接口、图片。

### F-08 窄屏溢出

- **复测动作**：Edge 无头将视口设为 320×700，访问首页/购物车/订单页，读 `document.documentElement.scrollWidth`。
- **修正前**：`scrollWidth=382 > 320`，右侧“加入购物车”被裁切（截图 `shots/h5-06-home-320.png` 早期版本）。
- **修正后**：三页均为 `320 = 320`；分类名与按钮完整显示。
- **证据**：`evidence/browser-check.json`、`evidence/shots/h5-06-home-320.png`、`h5-07-cart-320.png`。
