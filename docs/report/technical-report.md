## 1 项目概述

### 1.1 背景与目标

东华大学松江校区食堂在午晚餐高峰排队时间长、窗口信息不透明。本项目以课程允许的前后端分离形式，实现“学生手机点餐 + 食堂后台上架与处理订单”的最小闭环：学生可浏览菜品/套餐、加入购物车、选地址下单并模拟支付；员工可在管理端维护商品、处理订单、查看经营数据。

### 1.2 范围与形态

- 用户端为**移动 H5**（任务书允许 Vue3 + Vant 或微信小程序；因不具备小程序账号、认证与发布条件，选择 H5）。
- 管理端为 **Web**（Vue3 + Element Plus）。
- 课程内**不接入**真实短信、真实支付、微信登录、OSS 上传与消息推送；登录使用受控测试身份，支付为本地模拟。
- 课程内两人：刘晟玺、钱文博，不设第三名成员。

## 3 技术方案

### 3.1 架构

```text
用户 H5 (Vue3+Vant, 5173/8081)      管理 Web (Vue3+ElementPlus, 5174/8082)
        │  /user/**                          │  /admin/**
        └──────────────┬─────────────────────┘
                       │ 同源（开发期 Vite 代理；部署期 Nginx 反代）
              Spring Boot 2.7 (8080)：Controller → Service → Mapper(XML)
                       │
                  MySQL 8.0（takeout_course，11 张表）
```

### 3.2 技术栈（实测版本）

| 层 | 选型 | 版本 |
| --- | --- | --- |
| 后端 | Java / Spring Boot / MyBatis | 17.0.20.1 / 2.7.3 / mybatis-starter |
| 数据库 | MySQL | 8.0.46 |
| 构建 | Maven | 3.9.9 |
| 前端 | Vue / Vite / Pinia / Vue Router | 3.5 / 6.4.5 / 2.3 / 4.5 |
| UI | Vant（H5）/ Element Plus（管理端） | 4.9 / 2.9 |
| HTTP | Axios | 1.7 |
| 测试 | Node 脚本 + Edge headless(CDP) | Node 22.19 / Edge 156 |

### 3.3 关键决策

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 认证 | JWT + `Authorization: Bearer`，用户/员工双域密钥 | 前后端分离，令牌自包含；双域隔离防越权 |
| 口令存储 | PBKDF2 + 随机盐 | 不存明文；优于 MD5 |
| 支付 | 本地模拟，`PUT /user/order/payment` 只改状态 | 课程不接第三方，避免密钥与合规问题 |
| 金额 | `DECIMAL(10,2)`，JSON number；下单时后端按现价重算 | 客户端金额不可信；已验证伪造 0.01 无效 |
| 会话状态 | 不引入 Redis；营业状态存进程内 | 减少环境依赖，课程可接受（重启恢复） |
| 鉴权头 | 保留旧 `token`/`authentication` 兼容，新接入统一 Bearer | 兼容参考页面 |
| 路由 | hash 模式 | 静态托管无需服务端回退 |
| 跨域 | 不开 CORS，开发期 Vite 代理、部署期 Nginx 反代 | 同源最简单，减少故障点 |
| 前端 Mock | 契约冻结后删除，直连真实后端 | Mock 易与契约漂移 |

## 4 数据库设计

11 张表：`employee`、`user`、`category`、`dish`、`dish_flavor`、`setmeal`、`setmeal_dish`、`address_book`、`shopping_cart`、`orders`、`order_detail`。

要点：

- **逻辑外键**（不加物理外键），删除约束由 Service 校验（分类被引用、菜品被套餐引用时拒绝）。
- 状态用 `INT` + CHECK 约束：`status ∈ {0,1}`；订单 `status 1~6`、`pay_status 0~2`。
- 金额 `DECIMAL(10,2)`；时间 `DATETIME`（`Asia/Shanghai`）。
- 订单保存**收货信息快照**与**订单明细快照**（商品名/单价/口味），后续改价改名不影响历史单。
- 索引：`employee.username` 唯一、`category(type,name)` 唯一、`dish(category_id,status)`、`orders(user_id,order_time)`、`orders.status`、`order_detail.order_id` 等。
- 种子数据：2 分类 / 2 菜品 / 1 套餐 / 2 用户 / 2 地址，菜品图用后端静态 `svg`。

详见 `docs/leader/week2/database-design.md` 与 `schema.sql`。

## 7 前端实现（组员）

### 7.1 工程结构

```text
code/frontend/
├─ pnpm-workspace.yaml / .npmrc / package.json     # 工作区、镜像、store 位置
├─ user-h5/    src/{api,mock→已删,router,stores,views,utils,styles}
└─ admin-web/  src/{api,router,stores,views,layout,constants,styles}
```

### 7.2 请求层（两端同构）

- Axios 实例：`baseURL` 为空（路径与契约一致）；超时 15s。
- 请求拦截：注入 `Authorization: Bearer <token>`；用户令牌键 `sky_user_token`、员工 `sky_admin_token`，互不通用。
- 响应拦截：`code===1` 返回 `data`；否则抛 `ApiError(code, msg)`；HTTP 401 清令牌并跳登录，保留 `redirect`。
- 页面只调用 `src/api/*.js`，组件内不拼 URL、不判 HTTP 状态。

### 7.3 页面与交互

- 用户 H5（12 路由）：登录（两受控身份）、首页（分类侧栏 + 菜品/套餐 + 搜索 + 打烊提示）、菜品详情（口味标签 + 数量）、套餐详情（组成清单）、购物车（步进器改数量、滑动删除、清空）、确认订单（地址选择弹层、备注）、模拟支付对话框、订单列表（状态 tab + 取消/再来一单/催单）、订单详情、地址列表/编辑、个人中心。
- 管理 Web（7 页面）：登录、工作台（经营数据卡 + 订单状态计数 + 营业额报表 + 顶栏营业开关）、订单管理（条件查询、详情抽屉、按状态显示接单/拒单/派送/完成/取消）、分类、菜品（含口味编辑，值以 JSON 数组提交）、套餐（含组成编辑）、员工管理。
- 细节：提交按钮 loading 防重复、失败提示用后端 `msg`、空状态与错误状态、金额按 `单价×数量` 展示、口味兼容 JSON 串与逗号串。

### 7.4 构建与优化

- Vite 构建：用户端 29 文件 / 619 KB；管理端 25 文件 / 1.64 MB。
- 管理端 `manualChunks` 分包：业务入口 **9.7 KB**、`element-plus` 1.09 MB、`vue-vendor` 114 KB、`axios` 51 KB；改业务代码只需重下 9.7 KB。
- 响应式：390 / 1280 / **320** 三种宽度实测无横向滚动（320px 问题见 F-08）。
