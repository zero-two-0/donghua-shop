## 1 目标与范围

为校园食堂与商户提供浏览器内可演示的点餐闭环。用户端使用 Vue 3 + Vant H5，管理端使用 Vue 3 + Element Plus，通过同一 Java 后端访问 MySQL 业务数据。H5 是任务书允许的方案，可规避当前小程序账号、认证和发布条件的阻塞。

本期角色是点餐用户与商户员工。单校区、单商户课程演示为范围基线，不提供多商户结算、真实支付、短信认证、第三方配送或正式微信登录。课程测试登录替代正式账号注册/登录：首次使用测试身份建立测试用户，后续登录对应同一身份；该模式只用于受控课程环境。个人中心以查看当前测试身份及本人订单、地址入口为基础，正式账号找回和实名验证不在范围。

任务书中的日/周营业统计、工作台属于需求；Redis 缓存和 WebSocket 推送属于技术能力，需单独记录实现与实测。主流程可以主动查询订单状态；推送未验证时不得称已完成实时通知。所有偏离任务书的部分由组长登记并按课程要求沟通，不伪造教师批准。

## 2 角色、权限与术语

| 角色 / 术语 | 定义 |
| --- | --- |
| 点餐用户 | 维护本人购物车、地址和订单；无管理权限 |
| 员工 | 使用管理端登录，维护商品并处理订单；用户 JWT 不得替代员工 JWT |
| 在售 / 停售 | 商品是否允许新增购买；不改变历史订单明细快照 |
| 模拟支付 | 本地检查归属与状态后变更支付/订单状态，无真实扣费或退款 |
| 接口基线 | 经实际评审的 OpenAPI 版本；当前文件存在不代表双方已冻结 |
| 完成 / 验收 | 文档成稿、代码实现、自动化测试、环境验收分别判定，不相互替代 |

## 3 功能需求

优先级 P0 为主流程和安全底线；P1 为任务书完整业务要求；P2 为可选体验增强。本文列的是要求，是否实现及通过测试由交付报告提供证据。

| ID | 优先级 | 需求与后端验收条件 |
| --- | --- | --- |
| FR-AUTH-01 | P0 | 课程测试用户登录并签发用户 JWT；同一测试身份可再次识别；缺失/非法参数明确失败，不调用微信服务 |
| FR-AUTH-02 | P0 | 员工以用户名、密码登录并获得员工 JWT；错误凭据不签发令牌，返回中不包含密码/密码摘要 |
| FR-AUTH-03 | P0 | 受保护接口校验 Bearer 令牌、有效期和身份域；无效令牌拒绝访问；每次请求后清理线程身份上下文 |
| FR-USER-01 | P0 | 用户查询可用分类、在售菜品和套餐；支持按分类筛选及菜品关键词查询；停售商品不能新增购买 |
| FR-USER-02 | P1 | 提供个人中心所需的当前身份信息及本人地址/订单入口数据；不返回其他用户身份数据 |
| FR-CART-01 | P0 | 用户加购菜品或套餐，商品类型互斥、商品存在且在售；重复加入同一规格项时数量增加，价格来自服务端 |
| FR-CART-02 | P0 | 查询本人购物车，修改数量、删除单项及清空；数量为正整数，删除/改量不允许修改他人项目 |
| FR-ADDR-01 | P0 | 新增、查询、修改、删除本人地址；必填收货人、电话和地址，查询和修改均校验归属 |
| FR-ADDR-02 | P1 | 设置本人默认地址，同一用户至多一个默认项；非法/他人地址失败时不能清除原默认地址 |
| FR-ORDER-01 | P0 | 从本人非空购物车和本人地址创建订单；重新核验商品、数量和价格；前端金额不作为可信结算来源 |
| FR-ORDER-02 | P0 | 下单生成订单和商品快照后清空购物车，三项在同一数据库事务内完成；失败需回滚，不产生半张订单 |
| FR-ORDER-03 | P0 | 仅本人可模拟支付待付款订单；首次成功进入待接单；重复请求不产生重复扣款/状态倒退；不调用真实支付 |
| FR-ORDER-04 | P0 | 分页查询本人历史订单、详情与状态；可按状态筛选；其他用户订单详情、操作均被拒绝 |
| FR-ORDER-05 | P1 | 用户按契约允许状态取消订单；已完成/已取消订单不可重复迁移；模拟退款只记本地状态 |
| FR-ORDER-06 | P1 | 提供再来一单和催单能力时必须校验订单归属；再来一单重新检查商品可售性，不能直接照抄历史价格 |
| FR-ADMIN-01 | P1 | 分类新增、修改、分页、启停及删除；有关联商品时拒绝直接删除，给出可理解原因 |
| FR-ADMIN-02 | P0 | 菜品新增、修改、查询、删除、起售/停售；口味和价格可维护，历史订单快照不随菜品修改而变化 |
| FR-ADMIN-03 | P1 | 套餐及套餐菜品组成维护、查询、起售/停售；检查分类/菜品存在及关联删除限制 |
| FR-ADMIN-04 | P0 | 员工查询订单、接单、拒单、取消、派送、完成；仅允许下述状态迁移，失败不改变原状态 |
| FR-ADMIN-05 | P1 | 员工账号新增、修改、分页、启停；停用账号不得成功登录；响应隐藏密码及其摘要 |
| FR-SHOP-01 | P1 | 员工设置营业/打烊，用户查询营业状态；是否允许打烊下单应在契约与实现统一，禁止前后端各自猜测 |
| FR-REPORT-01 | P1 | 按日期范围查询营业额、有效订单量与日/周统计；定义有效订单为已完成订单，取消单不计收入，课程金额无真实营收含义 |
| FR-REPORT-02 | P1 | 工作台提供待接单/待派送/派送中数量和商品状态概览；统计口径与列表过滤保持一致 |
| FR-NOTIFY-01 | P2 | 在具备 WebSocket 通道验证后推送新订单/状态变化；仅发送授权范围事件；未接入时通过查询完成状态跟踪 |

### 3.1 订单状态约束

| 当前订单状态 | 允许事件 | 目标状态 | 执行角色 |
| --- | --- | --- | --- |
| 1 待付款 | 模拟支付成功 | 2 待接单 | 本人用户 |
| 1 待付款 | 取消 / 超时关闭（若启用） | 6 已取消 | 本人用户 / 系统 |
| 2 待接单 | 接单 | 3 已接单 | 员工 |
| 2 待接单 | 拒单 / 允许的取消 | 6 已取消 | 员工 / 本人用户（以契约规则为准） |
| 3 已接单 | 开始派送 | 4 派送中 | 员工 |
| 3 已接单 | 管理取消并说明原因 | 6 已取消 | 员工 |
| 4 派送中 | 完成 | 5 已完成 | 员工 |
| 5 已完成 / 6 已取消 | 无后续业务迁移 | 保持原状态 | 无 |

支付状态与订单状态分开：0 未支付、1 已支付、2 已模拟退款。取消已付订单时更新课程支付记录；失败操作不改变状态。具体接口枚举以 OpenAPI 为唯一调用依据。不能由用户直接调用管理完成接口。

## 4 核心用例

### UC-01 用户下单并完成配送

- 参与者：已登录用户、员工。
- 前置条件：系统有在售商品；当前用户有本人地址；服务具备可写业务数据库。
- 主流程：用户浏览商品→加入购物车→确认地址→提交订单→后端重算金额并生成快照→模拟支付→员工接单→派送→完成→用户查询最终状态。
- 成功结果：订单金额与服务端商品及数量一致；订单明细保留成交快照；购物车已清空；最终订单状态为 5，支付状态为 1。
- 异常：空购物车、地址越权、商品停售、数量错误、重复付款、非法状态操作均明确失败，不留下部分写入。断网后由用户重新查询订单确认结果，不由页面自行假定成功。
- 对应需求：FR-AUTH-01/03、FR-USER-01、FR-CART-01、FR-ADDR-01、FR-ORDER-01 至 04、FR-ADMIN-04。

### UC-02 管理商品并验证用户展示

员工登录→创建分类→新增菜品/套餐→起售→用户查询可见→停售→用户新增加购失败。有关联商品的分类删除应被拒绝。覆盖 FR-ADMIN-01/02/03、FR-USER-01、FR-CART-01；页面结果需第 6 周真实联调确认。

### UC-03 两个用户资源隔离

建立两个独立测试身份 A/B。A 创建地址、购物车和订单；B 使用 A 的资源 ID 请求查询、修改、删除、支付和催单，均不得读取或改变 A 的资源。A 原有数据保持不变。覆盖 FR-AUTH-03、FR-CART-02、FR-ADDR-01/02、FR-ORDER-03/04/06。

## 5 非功能需求与量化验收目标

以下是计划验收目标，不是现有性能或可用性声明。第 7 周执行时记录机器、数据库、数据规模、并发、样本量、命令和原始结果。

| ID | 要求 / 量化目标 | 验证方法与计划节点 |
| --- | --- | --- |
| NFR-SEC-01 | 所有受保护路由都必须拒绝缺失、过期、非法/错误角色令牌；用户资源越权用例通过率 100% | 第 4 周核心自动化测试，第 7 周 HTTP 回归 |
| NFR-SEC-02 | 源码/示例配置/日志中真实密钥、密码、完整令牌泄露数为 0；密码不明文存储；已复用摘要算法弱点须披露 | 第 4 周静态检查和登录响应测试，第 7 周补查日志 |
| NFR-DATA-01 | 订单/明细/清购物车任一步写失败全部回滚；金额精确到分，不用浮点结算 | 单元测试规则 + 第 7 周 MySQL 事务故障测试 |
| NFR-PERF-01 | 本机或统一演示机，10 并发、100 个在售菜品、至少 500 次请求时，浏览接口 p95 ≤ 1 秒、非预期失败率 < 1% | 第 7 周实测；网络及运行参数必须留存 |
| NFR-PERF-02 | 相同环境，5 并发、至少 100 次模拟下单时，p95 ≤ 2 秒；只计服务端响应，不计人工操作 | 第 7 周隔离测试数据实测，不写成生产容量 |
| NFR-COMP-01 | 一款桌面 Chromium 浏览器及一款手机浏览器可完成核心闭环；记录实际版本 | 第 6/7 周由前端配合验收 |
| NFR-API-01 | 契约覆盖本期暴露接口；所有必填、枚举、分页、鉴权和错误响应有定义；接口变更同步文档 | 第 3 周静态校验，第 4/6 周实现对照 |
| NFR-OBS-01 | 登录结果、下单、模拟支付、订单迁移、异常均有摘要日志；不得记录密码/token/完整地址 | 第 4 周代码检查，第 7 周运行日志抽查 |
| NFR-REPRO-01 | 两人按同一 README 在具备 JDK17/MySQL 等前置条件的环境可复现构建和启动 | 第 4 周构建，第 8 周独立复现；真实数据初始化另行授权 |
| NFR-MGMT-01 | 8 个里程碑各有交付索引；所有实际合并有 PR 和另一人审阅证据；重要缺陷有负责人/状态 | 各周验收；尚未建远程仓库时明确“待建立”，不得填写虚构链接 |

## 6 需求追踪与验收分层

| 需求集合 | 主要设计 / 接口区域 | 第 4 周优先验证 | 后续环境验证 |
| --- | --- | --- | --- |
| AUTH / SEC | 认证、JWT 拦截器、用户/管理登录 | 鉴权、身份域、上下文清理、响应脱敏 | 浏览器过期登录与重新登录 |
| USER / CART / ADDR | 商品、购物车、地址服务与用户接口 | 数量、商品校验、归属、默认地址 | MySQL 持久化和页面交互 |
| ORDER | 订单事务、金额、支付与迁移接口 | 重算金额、订单归属、幂等和状态边界 | MySQL 回滚、重复 HTTP 请求、整链路 |
| ADMIN / SHOP | 管理接口与关联约束 | 业务校验、错误返回 | 数据维护、状态对用户侧影响 |
| REPORT / NOTIFY | 统计/工作台/推送设计 | 代码与契约一致性检查 | 统计数据核对、缓存失效和推送鉴权 |

单元测试证明单个业务规则，MockMvc 等接口测试证明路由/序列化和鉴权行为；它们均不自动证明 MySQL SQL、真实事务、Redis、WebSocket 或前端闭环。最终以实际报告区分这些证据。
