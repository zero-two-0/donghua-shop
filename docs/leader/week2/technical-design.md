## 1 架构和选型

```text
用户 H5（Vue 3 + Vant）       管理 Web（Vue 3 + Element Plus）
             \                 /
                HTTP / JSON
         Nginx（第 8 周部署验证）
                Spring MVC
       JWT 拦截器 → Controller → Service（校验/事务）
                                  ↓
                           Mapper / MyBatis
                                  ↓
                               MySQL 8
                Redis（热点缓存/营业状态，按运行验证）
                WebSocket（订单通知，按鉴权与联调验证）
```

| 领域 | 选型 | 原因与约束 |
| --- | --- | --- |
| 后端 | Java 17、Spring Boot 2.7.3、Spring MVC | 与复用基线一致；课程实现保持版本收敛，不为展示擅自迁移框架大版本 |
| 持久化 | MyBatis、MySQL 8、事务 | SQL 可审阅，订单写入有明确事务边界；金额用 DECIMAL / BigDecimal |
| 构建 | Maven 三模块 | 复用 common / pojo / server 结构，依赖与构建步骤统一 |
| 认证 | JWT、Bearer | 用户/员工独立签发与校验；密钥从运行环境读取，不提交私人配置 |
| 契约 | OpenAPI 3 静态 YAML | `docs/week3/openapi.yaml` 是设计与交接主依据，可导入接口工具 |
| 在线文档 | Swagger 2 / Knife4j | 沿用代码注解辅助调试；不把 Swagger 2 声称为自动生成的 OpenAPI 3，差异需同步检查 |
| 缓存 | Redis、Spring Cache（适用时） | 服务仍以 MySQL 为业务事实来源；缓存键、失效和依赖须实测，不能以 Redis 中旧值代替结算价格 |
| 前端与部署 | Vue 3 两端、Nginx | 本文只定义对后端的依赖；不代写组员页面实现；Nginx 部署第 8 周验收 |

## 2 本人模块与分层职责

| 模块 | 我的实现职责 | 不应放入该层的逻辑 |
| --- | --- | --- |
| `sky-common` | 统一结果、分页、异常、JWT、当前身份上下文、公共配置 | 页面业务和直接查询数据库 |
| `sky-pojo` | DTO 接收参数、Entity 映射数据库、VO 返回界面需要的数据 | 认证与订单状态转换 |
| `sky-server` Controller | 路由、参数、角色入口、调用 Service、响应包装 | 直接拼 SQL、相信客户端 userId/金额 |
| Service | 归属、商品/状态校验、金额计算、事务、课程模拟支付 | 依赖前端隐藏按钮作为权限控制 |
| Mapper / XML | 参数化 SQL、用户范围条件、分页、读写持久化 | 字符串拼接用户输入、跨层生成 token |
| 测试 | 用可控 Mapper/依赖测试关键规则与控制器；记录实际构建结果 | 把 Mock 成功当作 SQL/真实事务/前端验收 |

DTO 只接收业务允许修改的字段。userId、createUser、支付结果和金额等敏感字段由服务端确定。返回员工数据时不输出密码或摘要；订单明细返回成交快照，避免历史数据随商品价格变化。

## 3 接口与鉴权设计

- 路径按 `/user/**` 和 `/admin/**` 分域，登录、公开浏览的放行列表与实际 Controller 路径一致。
- H5 使用课程测试登录；管理端员工登录；受保护请求统一 `Authorization: Bearer <JWT>`。准确请求字段、是否兼容历史头、公开路由以 OpenAPI 与代码为准，不让前端猜测。
- 用户和员工使用不同身份声明/校验域，不能把用户 token 当员工 token。JWT 校验成功后写入当前请求身份，请求结束清理 ThreadLocal，避免线程复用串号。
- 查改地址、购物车和订单时，在 Service/SQL 校验当前身份与资源归属；不能只检验“已登录”。对不存在与他人资源不给出敏感详情。
- 成功结果采用 `{"code":1,"msg":null,"data":...}`；业务失败采用 `code:0` 和可理解的 `msg`；`data` 按契约可空。分页数据为 `total`、`records`。无效令牌返回 HTTP 401；其他 HTTP 与业务码行为逐项依契约，前端不能只看 HTTP 200 判断成功。
- 现有 `code` 是成功/失败标记，不虚构一套未实现的细分错误码。需要扩展时同时修改公共结果、OpenAPI、前端提示与测试。

密码不明文存储。复用实现如使用旧式摘要，只能如实说明兼容限制，不能写成已实现 BCrypt/Argon2；课程账号不得复用个人密码。JWT 密钥与数据库口令仅通过本地运行环境设置，示例配置只含占位符或非敏感演示参数。

## 4 购物车、地址与订单核心流程

### 4.1 购物车与地址

购物项必须唯一选择菜品或套餐；验证商品存在、在售，数量为正整数。重复加购基于数据库已有数量递增，不能使用请求中未提供的数量。列表/改量/删除/清空都限定当前用户。购物车金额用于展示，正式下单再读可信商品价格。

地址新增时用户 ID 由当前身份写入。修改、删除、查询详情、设置默认均先验证归属。默认地址的清除与设置使用事务，先验证目标，再取消原默认；无效或他人地址请求不能破坏原状态。单用户默认地址并发约束与真实事务效果需在 MySQL 验证，不能仅凭注解宣称已解决所有竞争问题。

### 4.2 下单事务

1. 从令牌读取 userId，验证地址存在且属于本人。
2. 读取本人购物车，拒绝空车及非法数量；按商品 ID 读取服务端价格/状态，拒绝已删除或停售商品。
3. 使用 BigDecimal 计算各项和总额；客户端 `amount` 不作为结算依据。配送费、打包费如保留，必须有一致的服务端规则和契约字段；未定义的费用不凭空叠加。
4. 写订单（待付款、未支付）、商品快照和数量，清空本人购物车；三项在同一数据库事务内。
5. 返回订单 ID、订单号、服务端金额和时间。异常回滚；订单号需唯一，不能只依赖毫秒时间假定绝不碰撞。

测试覆盖金额重算、空车、地址越权和失败路径。实际 SQL、数据库约束和回滚仍需连接 MySQL 验证。若本轮只进行了 Mockito 测试，报告必须写明。

### 4.3 模拟支付和状态转换

模拟支付只操作本人订单：待付款 → 待接单、支付状态未付 → 已付；重复已成功支付返回稳定结果，不重复产生支付副作用。拒单/取消按规则更新订单与本地模拟退款状态，不调用真实第三方支付。

员工才能接单、派送和完成；每个 Service 操作校验存在和当前状态，状态图见 SRS。用户订单详情、取消、再来一单和催单均检查归属。幂等的业务目标、单请求状态检查、并发条件更新与真实数据库竞争测试分开记录；未经并发测试不宣称实现了分布式 exactly-once。

## 5 数据、缓存与通知

核心实体和字段见数据库设计，SQL 是可审阅交付附件，不自动执行到现有数据库。订单保存地址/收货人和商品名称、价格、数量快照；删除/停售商品不删除历史订单。分类与商品/套餐有引用关系，删除前检查，避免孤立数据。

当前 `course` 实现使用 Spring simple 进程内套餐缓存与内存营业状态（初始营业、重启重置），不依赖 Redis。后续 Redis 可用于公开热点菜品列表和营业状态等读场景；启用前须验收对应键的失效。个性化购物车和地址不能放入共享公开键。购物车持久化以本项目实际 Mapper 为准，不因任务书提到 Redis 就声称已经迁移；JWT 校验也不等于 Redis 已实现令牌吊销。

WebSocket 用于订单事件体验增强，订单事实仍以数据库查询为准。若保留推送通道，需检查连接身份、接收对象及信息泄露；没有运行和鉴权验证前在报告列为未验收，不能让匿名广播承担业务权限。

## 6 日志、异常和配置

主流程记录操作名称、阶段、业务对象 ID、成功/失败、异常类别等摘要；禁止输出完整 token、登录 DTO 中密码、支付密钥和完整住址。日志示意字段：`operation=order_submit phase=completed userId=... orderId=... result=success`，不要求前端接触内部实现细节。

参数错误、资源不存在、越权、商品停售和状态冲突给稳定失败响应；未知异常由统一处理返回安全信息，详细栈仅留服务端。日志不能把预期业务错误伪装成成功，也不能吞掉事务异常继续下单。

课程登录和模拟支付明确标为课程能力；正式运行不得用任意测试身份冒充账号认证。外部微信、OSS、真实支付等服务不得成为本轮构建/自测的必要前提，不携带参考工程中的私人配置。

## 7 测试策略、交接与部署设计

| 层级 | 我负责的验证 | 能证明的范围 |
| --- | --- | --- |
| 构建 | Maven 模块编译、测试与打包 | 依赖/代码可构建；不证明外部服务可用 |
| 业务测试 | 购物车数量、地址归属、金额重算、支付与状态规则 | 可控依赖下规则正确 |
| 控制器/拦截器 | 路由、Bearer、请求/响应字段、身份隔离 | 测试覆盖路径的 HTTP 行为 |
| 持久化/事务 | 独立测试库 SQL、Mapper、事务与并发 | 仅在真实执行后认定通过；操作数据库需授权 |
| 集成 / 部署 | 第 6 周前后端联调，第 8 周 Nginx 代理与运行复现 | 完整浏览器与环境行为 |

第 4 周交接内容包括源码、OpenAPI 版本、测试报告、启动前置条件、测试身份说明和未验证项。第 8 周部署目标为前端静态文件由 Nginx 托管、后端独立运行、数据库/Redis 通过环境配置连接；当前不提前写成部署成功。准确运行命令以 [后端 README](../../code/backend/README.md) 为准。

## 8 设计决策与待评审

| 决策 | 理由 | 尚需真实确认 |
| --- | --- | --- |
| H5 代替小程序路线 | 任务书允许且无需发布认证 | 前端适配字段与素材成本，由组员评审 |
| 三模块复用 + 有限修正 | 一人一周后端，控制开发量 | 构建与核心自测，不能直接照搬可信结论 |
| 静态 OpenAPI 3 为主，在线 Swagger 2 为辅 | 兼容基线，交付可版本化契约 | 自动生成与静态契约偏差检查 |
| 单体服务 + MySQL 事务 | 满足课程闭环，不引入无关中间件 | 实际数据库回滚/索引/并发验证 |
| Redis / WebSocket 分项验收 | 避免基础闭环被增强技术阻塞 | 失效与权限实测；未通过如实写限制 |
