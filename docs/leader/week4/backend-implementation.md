## 1 交付目标与范围

第 4 周交付包包含正式 Java 源码、课程配置、业务修正、测试、运行交接和实际验证记录。用户端由 H5 调用，管理端由 Web 调用；前端开发由钱文博负责，本人不把旧 `code/h5-demo/` 或 Python Mock 作为正式后端成果，也不代填组员前端验收。

后端采用 Java 17、Spring Boot 2.7.3、Spring MVC、MyBatis、MySQL 8。默认 `course` profile，测试身份和模拟支付替代外部微信能力。PageHelper starter 调整为 1.4.7，以适配本项目 Spring Boot 2.7 基线。当前课程运行不需要 Redis；营业状态使用内存、缓存使用 simple，保留的 Redis/WebSocket 代码和依赖不能直接计入已验证功能。

## 4 对外业务口径

统一响应 `code/msg/data`：成功 `code=1`，业务失败 `code=0`；无效令牌 HTTP 401；分页在 `data.total/records`。身份以 JWT 为准，不信任客户端 userId。用户端课程登录 `/user/user/test-login`，员工登录 `/admin/employee/login`；调用细节只维护在 OpenAPI，不在此复制一套完整字段定义。

订单状态：1待付款→2待接单→3已接单→4派送→5完成，合法取消进入6。支付状态：0未付、1已付、2模拟退款。用户无管理完成权限，已完成/取消订单不能倒退。模拟支付返回的 `SIMULATED` 字段仅为课程兼容数据，不可用于真实微信支付。

下单商品价格、名称、图片重新读取并保存快照；客户端金额与打包费不参与结算。库存扣减、真实支付对账、多实例幂等和高并发容量不在已完成声明内，未实测数据不能作为答辩性能指标。

## 5 环境与启动交接

完整步骤见 [后端 README](../../code/backend/README.md)。需要 JDK17、Maven 和已授权准备的 MySQL8 课程库；在工程根目录执行 `mvn test`、`mvn package`，运行 `sky-server/target/sky-server-1.0-SNAPSHOT.jar`。本轮没有自动执行真实数据库建表、迁移或公开部署。

运行参数为 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、可选 `SERVER_PORT`。`COURSE_ADMIN_PASSWORD` 仅在 course 模式、admin 不存在且非空时创建管理员，不会重置已有账号；这是可选真实写库能力，必须在获准环境使用。JWT 不设置密钥时随机生成，重启旧令牌失效；需要稳定签名时通过环境属性设置用户/员工各自独立密钥，不提交到仓库。

测试可能采用可控 Mapper、Mock HTTP 或 H2；其具体执行结果由根测试报告汇总。H2 验证不代替 MySQL 方言、数据库索引、真实并发和部署复现。源码在本目录可审阅与正式环境可完整启动是两个不同结论。
