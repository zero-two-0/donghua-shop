## 2 本人提交的统一规则

| 项目 | 设计口径 | 评审重点 |
| --- | --- | --- |
| 认证 | `Authorization: Bearer <JWT>`；登录及明确公开的路由免认证，其余按用户/员工域校验 | 不要把用户 token 用于管理端；旧自定义头若兼容须显式说明 |
| 返回 | `code/msg/data`；成功 `code=1`，业务失败 `code=0`；无效 token HTTP 401 | 前端同时检查业务码；不能写成 `message`；nullable 按 Schema |
| 分页 | `page`、`pageSize` 请求；`data.total`、`data.records` 响应 | 页码起点、合法范围和空结果；不可另造 `list` / `rows` |
| 金额 | 人民币元，精确到分；后端 BigDecimal/数据库 DECIMAL；下单服务端重算 | JS 展示精度；客户端金额不可信；打包费/配送费口径必须明确 |
| 时间 | 统一记录的日期/时间格式，以契约字段示例为准 | 时区、日期范围端点含义；不要在页面自行猜格式 |
| ID 与归属 | 身份由 token 确定；用户业务不接收可信 userId | 他人资源 ID 的查询/改写/支付均拒绝；不可只靠按钮隐藏 |
| 订单枚举 | 1待付款、2待接单、3已接单、4派送中、5完成、6取消 | 管理完成不得放给普通用户；重复/非法状态请求不倒退 |
| 支付枚举 | 0未付、1已付、2模拟退款 | 模拟支付/退款无第三方请求；重复支付行为清楚 |
| 菜品/套餐 | 起售与停售、分类关系、口味、套餐组成按实际 Schema | 菜品和套餐 ID 不混用；停售后购物车/再来一单如何失败 |
| 错误 | 明确必填、范围、资源不存在、越权、非法状态等失败场景 | 不输出 SQL、堆栈、密码或 token；别伪造未实现的细分业务码 |

精确路径、字段名、参数位置（path/query/body）、请求示例和响应 Schema 以 YAML 为准。本表用于评审规则，不建立第二份互相漂移的接口定义。

## 3 可直接逐项填写的接口检查单

| 检查 ID | 检查项 | 我提供的核对方式 | 调用方实际结论 |
| --- | --- | --- | --- |
| API-01 | 路径和 HTTP 方法唯一、参数位置明确 | 对照 Controller mapping 与 OpenAPI paths，查漏/多余接口 | 待核对 |
| API-02 | 所有登录/公开/受保护路由的 security 一致 | 用无 token、错误域、合法 token 对照测试 | 待核对 |
| API-03 | 请求必填、长度、最小值、互斥字段齐全 | 地址、数量、商品类型和状态错误示例 | 待核对 |
| API-04 | 每个成功响应有具体 data Schema | 页面逐字段验证，避免仅用无结构 object | 待核对 |
| API-05 | 列表/分页/空结果可消费 | 用 records 为空、total=0、末页示例 | 待核对 |
| API-06 | 下单与模拟支付字段覆盖确认页 | 不使用页面总价作为最终金额；以返回金额更新展示 | 待核对 |
| API-07 | 主流程需要的失败情形可展示 | 空购物车、停售、地址失效、登录过期、订单状态冲突 | 待核对 |
| API-08 | 编辑回显不泄露敏感字段 | 员工响应不包含密码，地址/订单只本人可读 | 待核对 |
| API-09 | 订单状态与按钮规则明确 | 依 SRS 状态表核对接单/派送/完成与取消 | 待核对 |
| API-10 | 统计日期、有效单与金额口径一致 | 用已完成/取消订单样本核对报表 | 待核对 |
| API-11 | 版本、示例、文档能对应同一实现 | 同一 PR 同时检查 YAML、DTO/VO、测试与实现 | 待核对 |
| API-12 | 没有虚构验证/冻结结果 | 真实评论、问题和修订有据；未执行标“未执行” | 待核对 |

## 5 冻结条件与冻结后的变更

冻结需同时具备：三批检查已实际执行、P0 契约问题关闭、Schema/示例静态校验通过、与实现差异有清单、两人真实评审结论和可追踪版本。准备材料、复制代码、构建成功均不自动满足冻结条件。

冻结记录留空等待事实：

```text
实际冻结时间：
契约版本 / commit（已存在时填写）：
刘晟玺检查结论与证据：
钱文博检查结论与证据：
遗留问题与后续版本：
```

冻结后变更先登记影响的需求、接口、前端调用、数据和测试；在同一 PR 更新 YAML、实现、测试和必要说明，另一人审阅后合并。紧急修复也保留变更说明，不能口头改字段后等待对方猜测。
