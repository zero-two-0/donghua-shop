## 一、阶段任务完成情况

1. 第 1 周 需求基线：完成《工程项目管理》任务书分析，确认用户端不依赖微信小程序账号与发布条件、改用任务书允许的 Vue 3 + Vant H5；确定两人分工（组长负责总体、后端、数据库、契约与文档；组员负责两端前端、接入与联调）；把原 12 周计划收敛为 8 周，明确每周一个主要交付包；建立 Git Flow（main / develop / feature / release / hotfix）与 PR 互审规则。

2. 第 2 周 设计基线：完成技术方案（Java 17 + Spring Boot 2.7 + MyBatis + MySQL 8；Vue 3 + Vite；认证采用 JWT 分域；事务与并发口径）与数据库设计（11 张表：employee、user、category、dish、dish_flavor、setmeal、setmeal_dish、address_book、shopping_cart、orders、order_detail，含逻辑外键、状态 CHECK 约束与索引），并给出空库建表脚本 schema.sql 与数据字典。

3. 第 3 周 接口契约：一次性设计并冻结 63 个 HTTP 路径（用户端登录/分类/菜品/套餐/购物车/地址/订单/催单，管理端员工/分类/菜品/套餐/营业状态/订单处理/统计/工作台），统一为 code/msg/data 外壳、Bearer 鉴权、page/pageSize + total/records 分页、金额由后端按现价重算、订单状态 1~6 与支付状态 0~2 枚举；配套分批评审工作表（A 认证浏览、B 用户交易、C 管理统计）。

4. 第 4 周 后端交付：完成三模块后端（sky-common、sky-pojo、sky-server，175 个文件），课程适配包括白名单测试登录（demo-user / demo-user-2）、PBKDF2 加盐口令、Bearer 令牌双域隔离、资源归属校验、购物车数量修正、订单服务端计价与事务快照、模拟支付、条件状态迁移、营业状态与工作台统计、静态资源与 /openapi.yaml 托管；50 项自动化测试全部通过（H2 + MockMvc），契约静态一致性脚本核对 63 个路径与 72 个 Schema。

5. 前端交付（提前完成）：两端工程（Vue 3 + Vant 用户 H5、Vue 3 + Element Plus 管理 Web）按正式契约实现——用户端 12 个路由（登录、首页分类/搜索、菜品详情与口味、套餐详情与组成、购物车、确认订单、模拟支付、订单列表/详情/取消/再来一单/催单、地址增删改查与默认、个人中心、打烊提示），管理端 7 个页面（登录、工作台经营数据/订单计数/营业额报表、订单查询与接单/拒单/取消/派送/完成、分类、菜品、套餐、员工管理、顶栏营业开关）。

6. 真实联调（补齐组长报告中“未验证”的真实库部分）：按组长 schema.sql 建课程库 takeout_course（11 张表，种子 2 分类 / 2 菜品 / 1 套餐 / 2 用户 / 2 地址），用项目内 JDK 17 + Maven 3.9.9 打包成功，JAR 连真实 MySQL 启动并监听 8080；编写 37 项接口冒烟脚本按“登录→浏览→加购→改数量→建地址→下单→模拟支付→员工接单→派送→完成→统计”跑完整链路，结果 37/37 通过。

7. 工程化与交付物：统一仓库结构（code/backend、code/frontend、docs/leader、docs/integration）；脚本化环境搭建、建库、构建、启停、接口冒烟、环境自检；补齐页面-接口对应表、契约差异对照、缺陷台账、联调记录、前端自测记录、运行手册、GitHub 操作指引；完成 Git 初始化（单提交、main/develop 双分支、提交身份为本组邮箱）并配置远程仓库。

## 四、风险和问题

1. GitHub 推送尚未完成：远程已配置，本机执行推送时返回“Invalid username or token / Password authentication is not supported”，属于本机缺少可用凭证（未登录 Git Credential Manager、未生成 PAT），不影响本地仓库完整性，需本人在浏览器登录或生成 Token 后推送。

2. 契约与实现存在 3 处不一致：F-01 购物车 amount 实际存储单价而非行小计（易导致前端金额显示减半，前端已按 单价×数量 适配）；F-03 用户端菜品列表契约声明 Dish、实现返回含口味的 DishVO；F-05 口味字段为 JSON 字符串、需两端各自解析。建议在契约中统一说明或修订，否则后续换人接手容易踩坑。

3. 用户端缺少菜品详情接口（F-04）：详情页只能拉全量列表后本地定位，菜品规模大时浪费请求；员工改密也无接口（F-06），管理端编辑页只能改资料，已在页面标注限制。

4. 未验证范围需明确：浏览器逐页点击与截图、手机窄屏布局、跨用户越权用例（需两身份串跑）、Nginx 部署验收均未执行，目前只有接口级与构建级证据，不能写成“系统验收通过”。

5. 进度与评审风险：本次是按授权提前完成前四周材料与代码，第 2~4 周的“双方评审/冻结”尚未真实发生；组长的 SRS、技术方案、契约与我早期草案存在两套口径，若不在第 5 周前统一，课程报告中容易出现前后矛盾。

6. 工程遗留：管理端 Element Plus 全量引入导致主包约 1.27 MB；前端页面细节（Loading、空状态、表单校验一致性）仅做到可用，未按第 5 周标准打磨；本机处于 OneDrive 中文路径，曾遇到 Maven 写 ~/.m2 被拒、Tomcat 在系统 TEMP 建目录被拒、PowerShell 读取无 BOM 脚本吞行三个问题，换机需按运行手册操作。
