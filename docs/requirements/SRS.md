## 1 引言

### 1.1 目的

明确东华大学在线点餐系统在课程范围内要交付的功能边界、交互约定与验收标准，作为前端页面实现、OpenAPI 契约评审和测试用例编写的共同依据。

### 1.2 范围

系统采用前后端分离的 B/S 架构，包含两端：

- **用户端 H5**：移动浏览器访问，覆盖浏览、加购、下单、模拟支付、查单、地址、个人中心。
- **商家管理 Web**：桌面浏览器访问，覆盖员工登录、分类/菜品/套餐管理、订单处理、营业数据概览。

后端（Java 17 + Spring Boot + MyBatis + MySQL 8）由组长刘晟玺实现，本文档只定义前端依赖的接口行为与字段语义，不规定后端内部实现。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| 菜品（dish） | 可单独售卖的最小商品，含分类、价格、图片、口味选项 |
| 套餐（setmeal） | 由多个菜品组合而成的商品，价格独立于明细之和 |
| 购物车（cart） | 用户下单前的暂存区，按“商品 + 口味”维度合并计数 |
| 订单快照 | 下单时把商品名、单价、地址等复制进订单明细，后续改价改名不影响历史订单 |
| 模拟支付 | 课程内不接入真实支付，确认后仅把订单状态从“待付款”改为“待接单” |
| Mock 模式 | 前端内置的本地接口替身，用于契约冻结前并行开发，界面上必须可见标识 |

### 1.4 需求编号规则

`R-端-编号`：`R-U-xx` 用户端，`R-A-xx` 管理端，`R-C-xx` 公共/非功能。追踪关系见第 5 章。

## 2 项目概述

### 2.1 业务背景

东华大学松江校区食堂在午晚餐高峰排队时间长、窗口信息不透明。本系统让学生在手机上下单并选择取餐/送餐地址，让食堂工作人员在后台维护商品与处理订单。

### 2.2 用户角色

| 角色 | 登录方式 | 权限边界 |
| --- | --- | --- |
| 学生用户 | 手机号 + 固定验证码 `1234`（课程模拟） | 只能读写本人的购物车、地址、订单 |
| 食堂员工 | 账号 + 密码（`employee` 表，JWT） | 管理商品、处理订单、查看统计 |
| 未登录访客 | 无 | 可浏览分类、菜品、套餐；不可加购、下单 |

### 2.3 运行环境约束

| 约束 | 说明 |
| --- | --- |
| 用户端形态 | 移动 H5（任务书允许 Vue3 + Vant；不采用微信小程序，避免账号与发布审核阻塞） |
| 支付 | 仅模拟支付，不配置商户密钥、不调用真实支付渠道 |
| 短信 | 不接入短信服务，验证码固定为 `1234` |
| 浏览器 | 用户端：iOS Safari / Android Chrome / 桌面 Chrome 手机模拟；管理端：Chrome 或 Edge 最新版 |
| 网络 | 本机联调（前端 5173/5174 → 后端 8080），课程演示不要求公网部署 |

### 2.4 明确不做的事项

- 不做微信小程序、不做公众号、不做真实支付与退款对账。
- 不做骑手端、不做多门店/多商家、不做优惠券与会员积分。
- 不做图片上传服务（课程内图片字段可留空，前端显示占位图）。
- 不做消息推送与实时通信（订单状态由前端轮询/手动刷新）。

## 3 功能需求

### 3.1 用户端 H5

#### R-U-01 登录（模拟验证码）

- **输入**：手机号（11 位）、验证码（固定 `1234`）。
- **处理**：调用 `POST /api/user/auth/login`；成功后保存 JWT 与用户概要。
- **页面**：`/login`，默认预填测试账号 `13800001111 / 1234`，提供“填测试账号”按钮。
- **异常**：手机号格式错误 → 表单内提示；验证码错误 → 顶部 Toast 显示后端 `message`；网络异常 → “网络异常，请稍后重试”。
- **验收**：正确账号登录后 1 秒内跳转来源页（无来源页则进首页）；错误验证码不跳转且提示可见；关掉浏览器重开仍保持登录态（令牌持久化）。

#### R-U-02 分类与菜品浏览

- **输入**：分类切换、关键词搜索。
- **处理**：`GET /api/categories?type=1` 与 `GET /api/dishes?categoryId=&keyword=&page=&pageSize=`。
- **页面**：`/home`，左侧分类栏 + 右侧菜品列表（名称、描述、价格、加入购物车按钮）。
- **异常**：无在售菜品 → 空状态文案；接口失败 → 错误状态与“重新加载”按钮；关键词无结果 → 空状态。
- **验收**：切换分类只显示该分类在售菜品；停售菜品（`status=0`）不出现在用户端；搜索“牛肉面”命中对应菜品。

#### R-U-03 菜品详情与口味选择

- **输入**：菜品 id、口味单选、数量（1~99）。
- **处理**：`GET /api/dishes/{dishId}`；加入购物车 `POST /api/user/cart/items`，`dishFlavor` 传 `辣度:微辣` 形式的拼接串。
- **页面**：`/dish/:id`，含图片区、描述、口味标签、数量步进器、底部提交栏（实时显示小计）。
- **异常**：菜品不存在 → 错误页；未登录点“加入购物车” → 跳登录并在登录后回到本页；停售 → 提交按钮禁用。
- **验收**：选择“微辣 + 2 份”加入后，购物车出现 1 行且小计 = 单价 × 2。

#### R-U-04 购物车

- **输入**：数量增删、单条删除、清空。
- **处理**：`GET /api/user/cart`、`PATCH /api/user/cart/items/{itemId}`、`DELETE /api/user/cart/items/{itemId}`、`DELETE /api/user/cart`。
- **页面**：`/cart`，展示图片、名称、口味、小计、数量步进器；底部合计与“去结算”。
- **异常**：数量越界（<1 或 >99）拦在前端且后端二次校验；删除失败回滚显示；购物车为空 → 空状态。
- **验收**：数量改到 3 后小计与合计同步更新；清空后底部导航角标消失；金额与后端返回一致（前端不自行改价）。

#### R-U-05 提交订单与模拟支付

- **输入**：收货地址（必选）、备注（≤100 字）。
- **处理**：`POST /api/user/orders` 生成待付款订单；弹窗确认后 `POST /api/user/orders/{orderId}/mock-payment`。
- **页面**：`/order/confirm`（地址、商品清单、备注、提交栏）、支付确认对话框。
- **异常**：未选地址 → 提交按钮禁用；购物车为空 → 40903 提示；重复点击提交 → 按钮 loading 防止重复下单；重复支付 → 40904 提示“该订单已支付”。
- **验收**：下单后购物车清空、订单出现在“待付款”；模拟支付成功后订单变“待接单”并记录支付时间；金额由后端计算，前端不传金额。

#### R-U-06 订单列表与详情

- **输入**：状态筛选、分页。
- **处理**：`GET /api/user/orders?status=&page=&pageSize=`、`GET /api/user/orders/{orderId}`。
- **页面**：`/orders`、`/orders/:id`。
- **异常**：越权访问他人订单 → 40301 提示并返回列表；订单不存在 → 空状态。
- **验收**：状态标签与后端 `statusText` 一致；详情含商品明细、金额、地址、时间；待付款订单可在详情页再次发起模拟支付。

#### R-U-07 收货地址管理

- **输入**：收货人、手机号、区域、详细地址、标签、是否默认。
- **处理**：地址列表/新增/修改/删除四个接口。
- **页面**：`/addresses`、`/addresses/edit/:id?`。
- **异常**：手机号格式错误阻断保存；删除默认地址时后端返回 40902 并提示；无地址时新增的地址自动设为默认。
- **验收**：同一用户至多一条默认地址；默认地址在确认订单页默认选中。

#### R-U-08 个人中心

- **输入**：无。
- **处理**：`GET /api/user/profile`；展示昵称、手机号、地址数、订单数。
- **页面**：`/profile`，含订单/地址入口与退出登录。
- **验收**：退出后受保护页面立即跳登录；未登录时个人中心显示“去登录”。

### 3.2 商家管理 Web

#### R-A-01 员工登录

- **输入**：账号、密码。
- **处理**：`POST /api/admin/auth/login`；失败返回 40103，禁用账号返回 40302。
- **验收**：错误密码提示可见且不跳转；登录后进入工作台；令牌过期后任意页面操作自动跳登录。

#### R-A-02 分类管理

- **功能**：列表（按类型/名称筛选、分页）、新增、修改、删除。
- **约束**：同类型下名称唯一（40906）；分类下仍有菜品或套餐时禁止删除（40907）。
- **验收**：新增重复名称被拒绝并提示；删除被引用分类时提示原因且数据不变。

#### R-A-03 菜品管理

- **功能**：列表（名称/分类/状态筛选、分页）、新增、修改、起售/停售、删除。
- **约束**：名称必填、分类必选、价格 > 0；被套餐引用的菜品禁止删除（40908）。
- **验收**：停售按钮切换后列表状态与用户端可见性同步；表单校验不通过不发起请求。

#### R-A-04 套餐管理

- **功能**：列表、新增、修改、起售/停售、删除。
- **本期范围**：只维护套餐主体字段；套餐内菜品组合（`setmeal_dish`）的编辑界面列入第 5 周，不在第 3 周前实现。
- **验收**：状态切换生效；组合编辑入口明确标注“未实现”，不给出虚假可用界面。

#### R-A-05 订单处理

- **功能**：列表（订单号/状态/时间范围筛选、分页）、详情抽屉、状态推进。
- **状态机**：`2 待接单 → 3 已接单 → 4 派送中 → 5 已完成`；`2 → 6 拒单`、`1 → 6 取消`，迁移到 6 必须填写原因；其他迁移返回 40909。
- **验收**：按钮仅显示当前状态允许的动作；非法迁移后端拒绝且前端提示；拒单原因出现在订单详情。

#### R-A-06 营业数据概览

- **功能**：今日订单量、今日营业额、累计订单量、累计营业额、订单状态分布。
- **口径**：营业额只统计已支付且未取消订单；口径变化需同步更新契约与页面说明。
- **验收**：数字与订单列表按同一口径可对账；无数据时显示 0 而非空白。

### 3.3 公共能力

#### R-C-01 请求封装与鉴权

所有页面只能通过 `src/api/*.js` 访问后端；请求拦截器统一注入 `Authorization: Bearer <token>`；响应拦截器拆解 `{ code, message, data }` 外壳，`code !== 0` 统一抛错；HTTP 401 清除令牌并跳登录。

#### R-C-02 统一错误提示

错误提示使用后端 `message`；网络层失败给出固定文案；表单校验错误在字段旁就地显示，不弹窗。

#### R-C-03 Mock 开关

`VITE_USE_MOCK=true` 时启用本地 Mock，界面固定显示“Mock 模式”角标；生产构建默认关闭并直连真实后端。Mock 数据字段必须与契约一致，联调阶段逐项切换到真实接口。

#### R-C-04 移动适配

用户端以 390×844 为基准、最大宽度 480px；关键页面（首页、详情、购物车、确认订单）在 320px 宽度下不出现横向滚动。

## 4 非功能需求

| 编号 | 要求 | 可验证方式 |
| --- | --- | --- |
| N-01 | 受保护接口必须校验令牌；用户只能访问本人购物车、地址、订单 | 用 A 用户令牌请求 B 用户订单，期望 40301 |
| N-02 | 输入参数校验，错误返回统一结构（含 `code`、`message`） | 提交非法手机号/负数量，检查响应外壳 |
| N-03 | 订单金额由后端按商品价格计算，前端不采信自报金额 | 篡改前端金额字段后下单，核对订单总额 |
| N-04 | 密码不得明文存储 | 检查 `employee.password` 为散列值 |
| N-05 | 接口文档与实现一致 | 运行 `node tools/validate-openapi.js`，要求前端调用 100% 被契约覆盖 |
| N-06 | 主要页面在桌面与手机浏览器可完成演示 | 手动走查主流程（浏览→加购→下单→支付→接单→完成） |
| N-07 | 前端构建可重复 | 运行 `scripts/build-frontend.ps1`，两工程均产出 `dist` |
| N-08 | 数据可重建 | `scripts/db-init.ps1` 可在空库上重跑并得到相同种子数据 |

## 6 与计划书的差异与取舍

| 计划书表述 | 本文档处理 | 原因 |
| --- | --- | --- |
| 复用苍穹外卖管理端（Vue 2 + Element UI） | 不迁移旧代码，按 Vue 3 + Element Plus 新建，参考其信息架构 | 素材不在本机，且 Vue 2 已停止维护；迁移成本高于重写，需在第 2 周记录决策 |

| 统计图表 | 本期只做数字卡片 + 状态分布表格 | 图表库与设计时间未纳入第 1~3 周范围 |
