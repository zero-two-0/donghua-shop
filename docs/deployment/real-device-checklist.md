# 真机访问验证清单（手机 / 平板连局域网）

| 项 | 内容 |
| --- | --- |
| 目的 | 在**真实手机**上验证 H5 的可用性：能打开、能下单、布局不塌、交互不挡 |
| 前置 | 电脑与手机连**同一个 Wi-Fi**；后端 8080 与 nginx 8081/8082 已启动 |
| 本机现状 | 局域网 IP **192.168.110.172**（WLAN，/24）；nginx 监听 `0.0.0.0:8081/8082`；防火墙已有 `nginx` 入站 Allow 规则 |
| 已验证 | 从电脑用 `http://192.168.110.172:8081` 访问：首页 200、`/user/shop/status` 返回 `code=1`、8082 首页 200 |
| 未验证 | **手机实际打开**（本清单第 3 节，必须人工做） |
| 编写 | 钱文博 |

## 1 手机端地址

```
用户端  http://192.168.110.172:8081
管理端  http://192.168.110.172:8082
```

> IP 会变：换网络或重连 Wi-Fi 后用 `ipconfig` 看“无线局域网适配器 WLAN”的 IPv4 地址，或直接看 `.\scripts\start-nginx.ps1` 不会打印 IP，可用下面命令：
> ```powershell
> Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike '127.*' } | Select-Object IPAddress, InterfaceAlias
> ```

## 2 打不开时按顺序排查（从下往上）

| # | 现象 | 检查 | 处理 |
| --- | --- | --- | --- |
| 1 | 手机浏览器一直转圈/超时 | 手机和电脑是否同一 Wi-Fi（不是 4G/5G） | 切到同一 SSID |
| 2 | 同上 | 电脑能否自己打开 `http://192.168.110.172:8081` | 不能 → nginx 没起或端口不对：`.\scripts\start-nginx.ps1` |
| 3 | 手机提示“无法访问此网站” | 防火墙对 `nginx.exe` 是否有 Allow | 以管理员开 PowerShell 执行：`New-NetFirewallRule -DisplayName "nginx 8081-8082" -Direction Inbound -Program "D:\NLP_SVM_Project\nginx-1.31.8\nginx.exe" -Action Allow` |
| 4 | 能连但很慢/间歇失败 | 路由器是否开了「AP 隔离 / 访客网络隔离」 | 关掉 AP 隔离，或换手机热点（电脑连手机热点也行） |
| 5 | 页面能开但接口报错/一直 loading | 后端是否在跑 | `Invoke-WebRequest http://127.0.0.1:8080/user/shop/status` 看 `code` |
| 6 | 页面空白 | 是否用了 `https://` 打开 | 必须用 `http://`（本项目未配证书） |
| 7 | 手机开了代理/VPN | 关掉系统级代理或 VPN 再试 | — |

## 4 证据怎么留（写进课程报告用）

1. **手机型号 / 系统版本 / 浏览器**（例：iPhone 14 / iOS 18.2 / Safari；或 小米 14 / Android 15 / Chrome 131）；
2. **同屏截图**：登录页、首页、购物车、确认订单、支付成功、订单详情、地址页 —— 每张最好带上手机状态栏（能证明是真机）；
3. 出现问题时：截图 + 复现步骤 + 手机浏览器控制台（Safari 可在电脑“开发”菜单远程调试；Android 用 chrome://inspect）；
4. 把结论填进本清单第 3 节，并在 `docs/integration/test-report.md` 第 5 节把「真机/局域网」从“未执行”改成实际结论（有问题就写问题）。
